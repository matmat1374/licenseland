# پیشنهادات بهبود سایت — لایسنو (Liceno)

**تاریخ:** ۱۴۰۵/۰۶/۲۳ | **مکمل گزارش:** `docs/CODE_REVIEW_2026-09-14.md`
**پیش‌نیاز:** موارد بحرانی گزارش بازبینی (C1 تا C5) باید قبل از هر توسعهٔ جدید بسته شوند — هیچ بهبود رشدی روی پایهٔ ناامن معنا ندارد.

هر پیشنهاد به کد موجود اشاره می‌کند تا مشخص باشد پایه‌اش از قبل ساخته شده و چقدر کار باقی مانده.

## B. سیستم وفاداری (همین تازگی ساخته شده — کاملش کنید)

| # | پیشنهاد | پایهٔ موجود | تخمین |

## اولویت‌بندی پیشنهادی

**هفتهٔ جاری (بعد از بستن C1-C5 امنیتی):**
1. B4 (۲ ساعت) + C4 (۲ ساعت) — دو برد سریع بدون ریسک
2. A2 (۱ روز) — بازیابی فروشِ ازدست‌رفتهٔ محصولات ناموجود
3. D2 (نیم روز) — چشم ادمین روی حوادث

**ماه جاری:**
- B1 (معرف) — ارزان‌ترین کانال جذب
- C1 + C2 — تجربهٔ پس از پرداخت که الان ضعیف‌ترین حلقه است
- D1 + D3 — عملیات قابل اتکا
- E1 + E2 — زیرساخت سرعت

**سه ماه آینده:**
- A1 + A3 + A5 (اعتماد داده‌محور)، F1 (کیف پول)، F2 (تامین‌کنندهٔ دوم)، D4، F4

**قاعدهٔ انتخاب:** هر قابلیت جدید قبل از شروع، پاسخ این سوال را باید داشته باشد: «کدام متریک UNIT_ECONOMICS را حرکت می‌دهد؟» (AOV، نرخ تبدیل، نرخ شکست تامین، CAC، LTV). اگر جواب ندارد، صف شود.
