# ADR-0009 — Vault لایسنس با Envelope Encryption

- **وضعیت:** پذیرفته‌شده
- **متنازع:** در ریپوی فعلی `LicenseKey.key` متن ساده است و فایل دیتابیس در ریپوی عمومی ترک شده → هر لایسنس موجود را باید افشاشده فرض کرد.

## تصمیم

| لایه | مکانیزم |
|---|---|
| کلید داده (DEK) | تولید تصادفی ۳۲ بایتی برای **هر** لایسنس |
| رمزنگاری محتوا | `aes-256-gcm` با IV ۱۲ بایتی یکتا + تگ احراز |
| پیچش کلید (KEK) | کلید اصلی ۳۲ بایتی فقط از ENV؛ DEK با همان الگوریتم پیچیده می‌شود |
| اتصال به متن (AAD) | شناسه سفارش؛ جابجایی لایسنس بین سفارش‌ها را رد می‌کند |
| چرخش کلید | `keyVersion` در رکورد ذخیره می‌شود؛ چرخش بدون بازرمزنگاری کل دیتابیس |

تست‌های الزامی که می‌گذرند: کلید اشتباه، AAD اشتباه، ciphertext دستکاری‌شده، کلید پیچیده دستکاری‌شده، و کلید با طول غیر ۳۲ بایت → همه `VaultError`. دو رمزنگاری متوالی از یک متن، ciphertext متفاوت تولید می‌کند.

## قواعد عملیاتی

- لایسنس رمزگشایی‌شده هرگز لاگ یا کش نمی‌شود؛ هر بازبینی در `audit_logs` ثبت می‌شود.
- اگر `LICENSE_VAULT_KEY` گم شود، لایسنس‌ها **برای همیشه** غیرقابل بازگردانی می‌شوند. نگهداری و پشتیبان جداگانه کلید از پشتیبان دیتابیس الزامی است.
- مهاجرت داده موجود: همه رکوردهای `LicenseKey` فعلی باید «افشاشده» علامت بخورند و ترجیحاً از تامین‌کننده تعویض شوند؛ رمزکردن دوبارهٔ یک راز لورفته، امنیت برنمی‌گرداند.
