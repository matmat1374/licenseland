# رویهٔ عملیاتی (SOP) + چک‌لیست کنترل کیفیت انتشار محصول

هدف: **هیچ محصول تکراری، متناقض یا بی‌مشخصات منتشر نشود.**

## بخش الف — SOP انتشار محصول جدید

| گام | مسئول | کار | خروجی | شرط عبور |
|---|-------|-----|--------|----------|
| ۱ | تحلیل/محتوا | استخراج مشخصات با «قالب درخواست اطلاعات» | JSON کامل | همهٔ ۱۲ فیلد ★ پر |
| ۲ | محتوا | ساخت عنوان با `NAMING_SKU_STANDARD.md` | عنوان + SKU | الگو رعایت شده |
| ۳ | محتوا | جست‌وجوی SKU و عنوان در پنل ادمین | نتیجهٔ جست‌وجو | **صفر** برخورد |
| ۴ | محتوا | بررسی پایهٔ برند/مدت مشابه | فهرست خانواده | نوع دسترسی متفاوت = عنوان باید متفاوت باشد |
| ۵ | فنی | ثبت محصول با `isActive=false` | ردیف پیش‌نویس | — |
| ۶ | QA | اجرای چک‌لیست بخش ب | گزارش QA | ۱۰۰٪ تیک |
| ۷ | مالک محصول | تأیید نهایی | تأیید | — |
| ۸ | فنی | `isActive=true` + بیلد + دیپلوی | محصول منتشر | صفحات ۲۰۰ |

**قاعدهٔ توقف:** اگر گام ۳ یا ۴ برخورد داد، محصول **منتشر نمی‌شود**؛ باید یا با محصول موجود ادغام شود (ریدایرکت) یا عنوان/نوع دسترسی اصلاح گردد.

## بخش ب — چک‌لیست کنترل کیفیت (پیش از `isActive=true`)

### عنوان
- [ ] الگوی `[برند] [نوع دسترسی] [سهمیه/سطح] ([مدت]) — [گارانتی]` رعایت شده
- [ ] نوع دسترسی صریح است (اکانت / سیت اشتراکی / API / گیفت‌کارت / شماره مجازی)
- [ ] سهمیه یا ارزش اسمی در عنوان آمده (برای API و گیفت‌کارت)
- [ ] مدت در پرانتز آمده
- [ ] عنوان با هیچ محصول دیگری **دقیقاً** یکسان نیست
- [ ] عنوان با محصول هم‌برند و هم‌مدت اما **کارکرد متفاوت** یکسان نیست
- [ ] عنوان ≤ ۷۰ کاراکتر
- [ ] واژه‌های تبلیغاتی جای ویژگی فنی را نگرفته

### SKU
- [ ] SKU ساخته شده و **یکتا**ست
- [ ] SKU با عنوان هم‌خوان است (تعداد/مدت یکسان)

### مشخصات
- [ ] مدت، سهمیه، تعداد کاربر، محدودیت منطقه‌ای، گارانتی و شرط تعویض پر است
- [ ] «تفاوت با نسخه‌های مشابه» برای خانواده‌های چندنسخه‌ای ثبت شده
- [ ] شرح کوتاه فارسی و قابل‌فهم است (نه متن خام انگلیسی تأمین‌کننده)

### قیمت و موجودی
- [ ] قیمت با `cost_usd` و نرخ روز دلار هم‌خوان است
- [ ] اختلاف قیمت با نسخهٔ مشابه، توجیه فنی دارد (نوع گارانتی/سهمیه)
- [ ] وضعیت موجودی واقعی است (نه عدد ثابت ۹۹)

### انتشار
- [ ] محصول پیش‌نویس با `isActive=false` ثبت شده
- [ ] تصویر و دستهٔ درست انتخاب شده
- [ ] پس از انتشار: صفحهٔ محصول ۲۰۰ است و در `/shop` درست دیده می‌شود

## بخش ج — اجرای آزمایشی روی محصول واقعی

**محصول تحت آزمون:** `Claude Pro (۱ روزه)` با شناسهٔ تأمین‌کنندهٔ `۲۳۷۵` (shortDesc: `API 10M Token Claude 1 Day - full warranty`)

| گام چک‌لیست | نتیجه |
|---|---|
| نوع دسترسی صریح | ✅ «API» استخراج شد |
| سهمیه در عنوان | ✅ «۱۰M توکن» |
| مدت در پرانتز | ✅ «(۱ روزه)» |
| یکتایی عنوان | ✅ با هیچ محصول دیگری یکسان نیست |
| یکتایی SKU | ✅ `CLAUDE-API-10M-1D` |
| هم‌خوانی SKU/عنوان | ✅ ۱۰M و ۱D در هر دو |
| گارانتی ثبت‌شده | ✅ «با گارانتی» |
| تشخیص برخورد خانواده | ✅ تفاوت با «۵۰M» و «۱۰۰M» در خود عنوان آشکار است |
| **نتیجهٔ نهایی** | **✅ عبور — قابل انتشار** |

**آزمون معکوس (باید رد شود):** عنوان `Claude Pro (۱ روزه)` بدون سهمیه → چک‌لیست در بند «سهمیه در عنوان» **قرمز** می‌شود و انتشار متوقف می‌گردد. یعنی چک‌لیست همان خطایی را می‌گیرد که امروز به‌وجود آمده.

## بخش د — قواعد ضدتکرار در سطح سیستم

این‌ها باید در کد اعمال شوند تا مشکل برنگردد:

1. **کلیدِ یکتایی محصول** = نرمال‌سازی (برند + نوع دسترسی + سهمیه + مدت). افزودن فیلد `dedupKey` با `@@unique` روی `Product`.
2. **مچینگ سینک** بر اساس `dedupKey`، نه فقط `supplier_product_id`.
3. **اصلاح `localizeProduct()`** مطابق `NAMING_SKU_STANDARD.md` (حذف نرمال‌ساز یکسان‌کننده).
4. **اعتبارسنجی پیش از ذخیره:** اگر عنوان تولیدشده با محصول فعال دیگری یکسان شد → به‌جای ساخت محصول جدید، ادغام/ریدایرکت.
5. **گزارش هفتگی:** اجرای `catalog-audit-registry.cjs` و بررسی ستون `issue_type` — هر ردیف جدید یعنی نشتی در فرایند.
