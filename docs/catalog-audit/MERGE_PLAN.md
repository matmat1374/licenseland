# برنامهٔ ادغام، آرشیو و ریدایرکت

قاعدهٔ طلایی: **هیچ ردیفی حذف نمی‌شود.** محصولات تکراری «آرشیو» (غیرفعال) می‌شوند تا ارجاع‌های سفارش (`OrderItem`) و کلید لایسنس (`LicenseKey`) دست‌نخورده بمانند و سئو از طریق ریدایرکت ۳۰۱ حفظ شود.

---

## ۱. قاعدهٔ تصمیم

| وضعیت | تصمیم | اثر روی دیتابیس |
|---|---|---|
| عضو تکراری (نام تأمین‌کننده یکسان) و **مبنا** | نگه‌داشتن (مبنا) | `isActive=true` + عنوان استاندارد |

**قید ایمنی مهم:** ادغام **فقط** داخل «گروه هویت تأمین‌کننده» انجام می‌شود (نام نرمال‌شدهٔ یکسان = همان محصول با شناسهٔ تازه). محصولاتی که فقط *عنوان* مشترک دارند هرگز ادغام نمی‌شوند و فقط عنوانشان اصلاح می‌شود. ابزار پیش از نوشتن، این دو شرط را اعتبارسنجی می‌کند: (۱) هر ادغام باید مقصد داشته باشد و مقصد هم‌کارکرد باشد (سهمیه و مدت یکسان)، (۲) هر گروه دقیقاً یک مبنا نگه دارد. خروجی فعلی: **۲۰۳ ادغام، همه با مقصد هم‌کارکرد و هم‌گروه، ۱۳۸ گروه با دقیقاً یک مبنا — صفر خطا.**
| عضو تکراری غیرمبنا | ادغام/آرشیو | `isActive=false` + ریدایرکت ۳۰۱ → مبنا |
| غیرفعال و منحصربه‌فرد | آرشیو + تغییر عنوان | `isActive=false` + عنوان استاندارد |
| فعال با عنوان گمراه‌کننده | تغییر عنوان | `title` جدید، `isActive` بدون تغییر |
| شمارهٔ مجازی | بدون تغییر | — (عنوان فعلی گویا است) |
| اطمینان پایین پارسر | **بررسی دستی** | بدون تغییر تا تأیید انسان |

## ۲. انتخاب «محصول مبنا»

به این ترتیب اولویت:
1. بیشترین `salesCount` (محصولی که واقعاً فروش داشته)
2. کم‌ترین `cost_usd` (بهترین حاشیهٔ سود)
3. جدیدترین `supplier_product_id` (فهرست‌بندی معتبرتر)

اسلاگ مبنا **تغییر نمی‌کند** تا رتبهٔ سئوی صفحهٔ اصلی حفظ شود؛ بقیه به آن ریدایرکت می‌شوند.

## ۳. نتیجهٔ اجرا روی کپی دیتابیس (راستی‌آزمایی‌شده)

```
کل محصولات:              ۱٬۰۴۹  (بدون تغییر)
آرشیو شده:                  ۸۴
تغییر عنوان:                ۸۳
فعال‌شدهٔ مجدد:              ۴۴
ریدایرکت افزوده:           ۲۰۳   (۷۷۷ → ۹۸۰)
حذف ردیف:                    ۰
گروه تکراری فعال باقی‌مانده:  ۰
گروه گمراه‌کننده باقی‌مانده:  ۱ (Genspark Plus — بررسی دستی)
سفارش‌ها و کلیدهای لایسنس:   دست‌نخورده ✅
```

## ۴. حفظ سئو

- اسلاگ مبنا ثابت می‌ماند؛ صفحهٔ علمی که رتبه دارد آرشیو **نمی‌شود**.
- ۲۰۳ ریدایرکت جدید در `src/data/slug-redirects.json` ادغام می‌شوند (فایل فعلی ۷۷۷ رکورد دارد و دست‌نخورده حفظ می‌شود).
- `src/middleware.ts` این نگاشت را اعمال می‌کند → ۳۰۱ از اسلاگ قدیمی به مبنا.
- `sitemap.ts` فقط محصولات فعال را می‌آورد؛ محصولات آرشیوی خودبه‌خود حذف می‌شوند.

## ۵. حفظ سابقهٔ سفارش

چون هیچ ردیفی حذف نمی‌شود:
- `OrderItem.productId` معتبر می‌ماند و تاریخچهٔ خرید کاربر به‌هم نمی‌ریزد.
- کلیدهای لایسنس صادرشده متصل به همان محصول باقی می‌مانند.
- محصول آرشیوی از فهرست `/shop` و صفحهٔ محصول حذف می‌شود، اما صفحهٔ سفارش کاربر همچنان کار می‌کند.

## ۶. اجرا

```bash
# ۱) بازتولید جدول ردیابی از دیتابیس فعلی
node scripts/catalog-audit-registry.cjs

# ۲) درای‌ران (بدون تغییر چیزی)
node scripts/catalog-dedup-apply.mjs

# ۳) تست روی کپی دیتابیس
cp prisma/db/custom.db audit-test.db
node scripts/catalog-dedup-apply.mjs --db "file:$PWD/audit-test.db" --apply

# ۴) اعمال روی پروداکشن (فقط پس از تأیید صریح)
node scripts/catalog-dedup-apply.mjs --apply
npm run build && pm2 reload licenseland
```

## ۷. بازگردانی (Rollback)

- **قبل از اجرا** از دیتابیس پروداکشن نسخهٔ پشتیبان بگیرید (`cp prisma/db/custom.db prisma/db/custom.db.pre-dedup`).
- فایل `src/data/slug-redirects.json` را کامیت کنید تا بازگردانی با `git checkout` ممکن باشد.
- چون هیچ ردیفی حذف نمی‌شود، بازگردانی = برگرداندن بکاپ دیتابیس + `git revert` کامیت ریدایرکت‌ها.

## ۸. اصلاح ریشه‌ای (پس از پاک‌سازی)

پاک‌سازی علائم را درمان می‌کند؛ برای جلوگیری از بازگشت باید در کد هم اصلاح شود:

1. در `rebuild-catalog.mjs` و `supplier.ts`: تطبیق با **کلید نرمال‌شدهٔ محصول** (برند + نوع + سهمیه + مدت) به‌جای `supplier_product_id` تنها.
2. نگه‌داشتن یک `dedup_key` روی مدل `Product` و `@@unique` روی آن.
3. اصلاح `localizeProduct()` طبق `NAMING_SKU_STANDARD.md`.
4. افزودن دروازهٔ QA (بخش SOP) که پیش از `isActive=true` تکرار را می‌گیرد.
