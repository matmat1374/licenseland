# اصلاح ریشه‌ای در کد — جلوگیری از تولید محصول تکراری

این سند بخش «پیشگیری» را از پیشنهاد به **کد اجراشده و تست‌شده** ارتقا می‌دهد. هیچ‌چیز روی پروداکشن دیپلوی نشده است.

---

## ۱. ماژول جدید: `src/lib/product-naming.ts`

تابع خالص (بدون دیتابیس) که هر دو ایراد ریشه‌ای را می‌بندد:

| تابع | نقش | رفع کدام ایراد |
|---|---|---|
| `parseAttributes(name)` | استخراج نوع دسترسی، سهمیه، مدت، سطح و گارانتی از نام تأمین‌کننده | M1 |
| `buildProductTitle(base, attrs)` | ساخت عنوانی که **همیشه** نوع دسترسی و سهمیه را نشان می‌دهد | M1 |
| `buildSku(brandCode, attrs)` | ساخت کد یکتای محصول | M1 |
| `buildDedupKey(name, opts)` | هویت پایدار محصول برای تطبیق سینک | M2 + M3 |
| `extractCountry(name)` | تفکیک شماره‌های مجازی بر اساس کشور | S3 |

## ۲. اتصال به خط تولید

### الف) اصلاح عنوان — `src/lib/supplier.ts` → `localizeProduct()`
پیش از این، هر نوع Claude به «Claude Pro» فروکاسته و فقط مدت اضافه می‌شد. حالا پیش از افزودن مدت:

```ts
const namingAttrs = parseAttributes(t);
const brandInfo = detectBrand(t);
const titleIsVirtual = /شماره مجازی/i.test(finalTitle) || namingAttrs.accessType === "virtual";
if (brandInfo && !titleIsVirtual && namingAttrs.accessType !== "unknown") {
  finalTitle = buildProductTitle(finalTitle, namingAttrs);
}
```

**قاعدهٔ ایمنی:** اگر نوع دسترسی قابل تشخیص نباشد یا محصول «شماره مجازی» باشد، عنوان **دست‌نخورده** می‌ماند. به همین دلیل تنها ۲۹ نام از ۱۰۴۹ نام تغییر می‌کند.

### ب) کلید تطبیق — `buildDedupKey`
کلید از «برند + نوع دسترسی + سهمیه + مدت + سطح» ساخته می‌شود، پس فهرست‌گذاری مجدد توسط تأمین‌کننده دیگر محصول جدید نمی‌سازد. شماره‌های مجازی با **کشور** کلید می‌خورند تا اشتباهاً ادغام نشوند.

## ۷. وضعیت انتشار

| مورد | وضعیت |
|---|---|
| ماژول + تست‌ها | ✅ آماده (typecheck و ۱۱۶ تست سبز) |
| اصلاح عنوان در `localizeProduct` | ✅ آماده |
| تعمیر mojibake | ✅ اعمال‌شده در ریپو |
| کلید ضدتکرار در سینک | ⏳ آماده برای اتصال (نیازمند تکمیل در هر سه نقطهٔ ساخت محصول + backfill) |
| دیپلوی روی پروداکشن | ⛔ بدون تأیید شما انجام نمی‌شود |

### گام بعدی پیشنهادی برای تکمیل اتصال
1. افزودن `dedup_key: buildDedupKey(shortDesc, { category: catSlug })` به `nextSpecs` در سه نقطهٔ ساخت محصول (`supplier.ts` ×۲ و `rebuild-catalog.mjs` ×۱).
2. افزودن شرط تطبیق `{ specifications: { contains: '\"dedup_key\":\"<key>\"' } }` به کوئری `existing`.
3. اجرای یک backfill یک‌باره برای محصولات موجود.
4. سینک آزمایشی روی سرور و بررسی «تعداد اضافه‌شده = ۰».
